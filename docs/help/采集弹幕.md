# 采集弹幕

把单个 B 站视频(含多 P)的**当前弹幕池全量**采集成结构化时间轴入库;之后 `export bundle` 自动携带弹幕原料,分析会话可回答「观众在哪个时间点反应强烈」。命令两件套:`danmaku collect` 采集入库 / `danmaku verify` 校验统计。

相关:[[采集模型]]、[[采集评论]]、[[导出分析原料包]](同类直连型入口)

> 下文命令在 `apps/collector-server` 目录执行(`npx tsx src/cli/main.ts`;全局选项 `--db/--server/--token/--format` 放子命令前)。

## 0. 前置

- **视频已入库**:弹幕挂在视频行上——库内没有该视频时先采视频([[采集单个视频]]),否则 collect 退 5 `video not found`
- **server 在跑**:`collect` 的定位与写库走 server HTTP(本地默认 `http://127.0.0.1:21527`;写生产库加全局 `--server <url> --token <t>`)
- **B 站 cookie(可选)**:与评论必配不同,弹幕接口匿名即可拿全量;有 cookie 降风控概率,没有照常跑(日志注明匿名采集)

```bash
node scripts/bili-cookie-from-chrome.mjs --refresh   # 可选:从 Chrome 拷 cookie → ~/Local/collector-secrets/bili-cookie.txt
```

也可 `--cookie-file <path>` 或环境变量 `COLLECTOR_BILI_COOKIE_FILE` 指定其他 cookie 文件;两者都没有时匿名跑,不报错。

## 1. dry-run 试跑(不写库)

```bash
npx tsx src/cli/main.ts danmaku collect --bvid <BV号> --dry-run
```

拉取、解析、stderr 日志照常,但不调写库接口。回执 `dry_run:true`,store 段变为 `would_requests`/`would_rows` 预估计数。

## 2. 全量采集

```bash
npx tsx src/cli/main.ts danmaku collect --bvid <BV号>
```

- 多 P 视频默认 `--page all` 全部串行采(每 P 独立弹幕池);只采某一分 P 用 `--page <n>`
- 分段拉取:每段 360 秒,段数按时长自动算,越界段(304)自动判停;请求量小,1 小时视频约 10 个请求
- 回执(stdout JSON):`pages`(各分 P 段数与条数)、`store`(inserted/updated)、`before_rows`/`after_rows`(本轮前后库内总量)、`verify`(内嵌校验)、`partial`(true 时带 `partial_reason` 说明判停原因)

## 3. verify 核对

```bash
npx tsx src/cli/main.ts --format json danmaku verify --bvid <BV号>
```

本地只读校验,建议 `--format json`(嵌套回执 table 形态不可读)。重点字段:

| 字段 | 怎么读 |
|---|---|
| `counts.rows` / `counts.by_page` | 库内弹幕总条数 / 各分 P 条数 |
| `timeline.peak_minute` | 弹幕最密的分钟桶(「哪分钟炸锅」的库内口径) |
| `timeline.histogram_60s` | 按 60 秒分桶的时间分布(消费端看热点段落) |
| `integrity.dup_id` | 重复唯一键计数(UNIQUE 约束下恒 0,非 0 即库损坏) |
| `integrity.negative_progress` | 非高级弹幕出现负时间点的条数(正常应接近 0;高级弹幕无时间点不计) |
| `weight` / `mode` / `ctime` | 屏蔽权重分位数 / 弹幕类型分布 / 发送时间范围(信息性统计) |

## 4. 重采语义

**全量重拉即增量**:每次采集都拉整个弹幕池,按弹幕唯一键 `id_str` 幂等 upsert——新弹幕插入、已有弹幕刷新,重复采集安全。

- 没有水位/增量机制(弹幕请求量小,全拉比水位便宜;与评论的水位追新不同)
- 被删除/淘汰的弹幕不会从库里物理删除,历史采集结果自然保留
- 重采刷新观测列(内容/时间点等),保留首采时间(`first_seen_at`)

## 5. popup 查看与复制

打开 **B 站视频页**,点扩展 popup(需扩展 0.1.35+,manifest 版本见 popup 品牌头):

- 弹幕卡默认**折叠**为一行:chevron + 弹幕条数 + 「复制」按钮(对齐「UP 全部视频」卡的展开形态)
- 点折叠行**展开**:定高可滚动列表,逐条 `[MM:SS] 内容`(时间轴序即接口顺序;无时间戳显示 `--:--`);再点收起,收起再展开不重新请求
- 点「复制」按钮一键批量复制全部弹幕为时间轴文本,每条一行 `[MM:SS] 内容` 格式(与展开列表同口径,与 bundle 正文同形态,可直接粘贴给分析会话;折叠态即可复制,不必先展开)
- 弹幕采集仍走上面 CLI,popup 只消费库内数据

## 6. 消费

`export bundle` 不需要新参数:库内有弹幕的视频自动导出 `danmaku/<BV号>.md` 时间轴正文(按分钟分桶,桶内按显示时间升序)+ manifest `danmaku` 摘要,格式见 [[导出分析原料包]]。

## 常见报错

| 现象 | 处置 |
|---|---|
| 退出码 2(ARGS) | 参数错:`--bvid`/`--aid` 双缺、`--page` 非法值、`--cookie-file` 路径不可读——按报错信息补参 |
| 退出码 3 | server 不可达:先起 server(`collector-cli server start`)或核对 `--server` |
| 退出码 5 `video not found` | 视频不在库:先采视频再采弹幕 |
| `risk_control` 类 partial(-352/-412 等) | 三档退避后仍失败:换时段/降频再跑;已入库部分不受影响(行级幂等,重跑安全) |

## 参数速查(danmaku collect)

| 参数 | 默认 | 说明 |
|---|---|---|
| `--bvid <bv>` | 与 `--aid` 至少其一 | 目标视频 BV 号(与 --aid 二选一或同给做交叉校验) |
| `--aid <n>` | — | 目标视频 av 号(单独给时经 view 接口回查 bvid) |
| `--page <all\|n>` | `all` | 多 P 选择:all=全部分 P 串行;n=只采第 n 个分 P |
| `--max-segments <n>` | `0` | 单 P 段数上限(0=不限,按时长 ceil(duration/360) 自动算) |
| `--max-requests <n>` | `300` | 单轮 B 站请求预算(用尽→partial request_budget) |
| `--segment-interval-ms <n>` | `1000` | 段间隔基数 ms(±30% 抖动) |
| `--batch-size <n>` | `2000` | ingest 批大小 |
| `--dry-run` | off | 只拉取解析不入库(回执 store 段为 would_requests/would_rows) |
| `--cookie-file <path>` | `$COLLECTOR_BILI_COOKIE_FILE` | cookie 文件(可选;缺省 env;都没有则匿名跑) |

`verify` 另有 `--bvid <bv>`(必填,目标视频 BV 号);回执格式走全局 `--format`。
