# 灾难重建

裸机(新机/重装系统)从零拉起生产:代码 → 配置 → 容器 → 数据 → 定时任务 → 客户端,按时间序一条龙。
数据源是异地副本(群晖同步盘);只要副本在,任何单机故障都可整机重建。

相关:[[Docker 部署]]、[[环境变量]]、[[客户端与任务派发]]

前提:本机装好 node 与 docker,`which node` 记下绝对路径(cron 必须用绝对路径——cron 的 /bin/sh PATH 无 nvm,裸 node 曾致异地导出静默断 40 天);异地副本目录可访问。

## 1. 代码

```bash
git clone git@github.com:743v45/subtitle-collector.git
cd subtitle-collector && pnpm install
```

## 2. 配置(.env)

仓库根新建 `.env`,token 用**新随机值**(旧机泄漏面未知,不沿用旧值):

```bash
COLLECTOR_TOKEN=<node -e "console.log(require('crypto').randomBytes(24).toString('hex'))" 的输出>
COLLECTOR_ALLOWED_HOSTS=<局域网 IP,暴露部署才需要>
COLLECTOR_BACKUP_WEBHOOK_URL=<飞书 bot 地址,可选>
```

暴露部署下占位符/空 token 会被启动闸直接拒绝启动——配错当场暴露,不用等出事。

## 3. 起容器

```bash
docker compose up -d --build
```

## 4. 恢复数据(群晖副本 → 卷)

`--apply` 只认卷内 `/data/backups/` 的备份,群晖副本要先灌进卷:

```bash
docker volume ls | grep collector-data        # 人工指认卷名(裸机场景容器可能被删,无挂载可反查)
docker cp <群晖副本>/bilibili-collector-backup-<时间戳>.db collector-server:/data/backups/
node scripts/backup-restore.mjs --apply bilibili-collector-backup-<时间戳>.db --volume-name <卷名>
```

`--apply` 全部前置校验(卷存在/生产库存在/目标备份在卷内)通过且交互输 yes 后才停服换库,旧库改名 `.pre-restore-<时间戳>` 留证,换完自动重启容器。

## 5. 定时任务(crontab)

`crontab -e` 重挂两行,node 一律绝对路径:

```bash
# 每日异地导出(分钟/小时随意,错开整点):
23 10 * * * <node 绝对路径> <仓库绝对路径>/scripts/backup-export.mjs "<异地目录>" --keep 1 >> <仓库绝对路径>/data/exports/offsite.log 2>&1
# 每周备份链路巡检:
43 10 * * 1 <node 绝对路径> <仓库绝对路径>/scripts/backup-healthcheck.mjs >> <仓库绝对路径>/data/exports/healthcheck.log 2>&1
```

## 6. 验收

```bash
node scripts/verify-deployed.mjs --via-docker collector-server --token <t>   # HTTP + DB integrity
node scripts/backup-healthcheck.mjs                                          # 备份链路四项
node scripts/env-inventory.mjs                                               # 外置配置五项(crontab/.env/cookie/异地/report 仓)
```

全绿即重建完成;恢复质量要数字见 `--apply` 末尾的 videos 行数与演练台账(docs/plans/acceptance-log.md)。
