# 导出分析原料包

`export bundle`:把一批视频的元信息 + 字幕打包成一个自包含的分析原料目录,喂给 [[分析工作流]]。

相关:[[检索视频库]](过滤器同源)、[[分析工作流]]

## 用法

生产数据源走 `scripts/export-bundle.mjs` 两步合一(生产库在 docker volume,宿主机严禁直开):① 容器内 `VACUUM INTO` 打新快照 + docker cp 到 `data/exports/`;② collector-cli `--db <快照> export bundle` 出包。一条命令:

```bash
# 按 UP 主打包(输出 analysis/某UP分析/bundle/)
node scripts/export-bundle.mjs --theme "某UP分析" --creator "某UP"

# 按标签打包
node scripts/export-bundle.mjs --theme "数据库专题" --tag "数据库"

# 任意组合过滤;24h 内打过快照则复用不打新
node scripts/export-bundle.mjs --theme "测试" --source bilibili --since 2026-07-01 --track-type 2 --max-age-hours 24
```

选项:`--theme <主题>` 决定缺省输出 `analysis/<主题>/bundle/`(目录不存在自动建);`--out <dir>` 显式指定输出目录(优先,已存在非空需 `--force`);`--max-age-hours <n>` 复用 mtime 最新快照(绝不按文件名猜);其余过滤器全量透传 collector-cli export bundle(`--tags` 多标签 AND 同源)。

直接对本地库(快照副本/dev 库)出包时才是 CLI 形态,过滤器与 `videos list` 完全一致,无分页——命中多少打包多少:

```bash
cd apps/collector-server && npx tsx src/cli/main.ts --db <db绝对路径> export bundle --creator "某UP" --out <绝对目录>
```

## 产物结构

```
<输出目录>/
├── manifest.json     # 批次元信息:过滤器、视频清单、轨道/版本选择
├── videos/
│   └── *.txt         # 一视频一文件,正文为「[分:秒] 字幕」行格式
├── comments/
│   └── <BV号>.md     # 评论区正文(库内有评论的视频才有;一视频一文件)
└── ANALYZE.md        # 给分析会话的说明(怎么读这批原料)
```

正文行格式示例:

```
[03:12] 这里我们看一下事务隔离级别
[03:18] 首先是读已提交
```

## 为什么是这个格式

- `[分:秒]` 前缀让分析时能**回溯时间点**(引用原视频第几分几秒)
- 一视频一 txt,分析会话按需读单文件,不用整包塞上下文
- manifest.json 记录批次构成,产物可追溯

## 评论区原料(已采集评论的视频自动附带)

库内有评论的视频,导出时自动多两件,无新参数([[采集评论]] 先采入库):

- **`comments/<BV号>.md`** 正文:根评论按点赞降序分组、组内楼中楼按时间;每条带赞数/昵称/IP 属地/发布时间,`(UP主)` 标 UP 本人发言,`[已折叠]`/`[仅自己可见]` 是平台状态标注,根被删的楼层归入文末「根已删除的楼层」组
- **manifest 视频条目 `comments` 字段**:`file`(相对路径)/ `roots`(根评论数,含置顶)/ `total`(总条数)/ `coverage`(楼中楼覆盖率 0-1)/ `like_top`(最高赞)/ `last_collected_at`

manifest **无** `comments` 字段 = 该视频未采评论(评论区关闭或未采集),属分析盲区;`coverage < 1` = 部分楼中楼缺失,对账清单用 `comments verify` 查。存量旧 bundle 不回填评论段。
