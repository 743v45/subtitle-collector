# 测试与质量门

什么时候跑什么。政策全文在 [CLAUDE.md §3](../../CLAUDE.md) 与 [docs/quality/RULES.md](../quality/RULES.md),本页是操作速查。

## 命令速查

| 命令 | 什么时候跑 | 内容 |
|---|---|---|
| `pnpm build` | 每次代码改动完成 | 测试 runner 不做类型检查,**测试全绿 ≠ 可构建** |
| `pnpm test` | 日常 | 三端单测(server c8 / web vitest / 扩展 c8),覆盖率锁定只升不降 |
| `pnpm qa` | **每次涉代码提交前(必跑)** | build + test --force + 覆盖率锁定 + 静态台账 + skill 同步 + depcruise;结果写进 commit message |
| `pnpm test:ext` | 扩展链路改动后(本地) | puppeteer mock 扩展端到端回归,不进 qa |
| `pnpm test:youtube` | 涉 YouTube 采集的改动后(本地) | 同上,YouTube 链路 |
| `pnpm verify:deployed` | 部署后 | /ping + 核心只读 API + SQLite integrity_check(带 `--db` 才测库,见 [[Docker 部署]]) |

## pre-commit(husky)

提交时自动跑,只查 git 新增文件的两条静态规则。**不代替 `pnpm qa`**——qa 是手动纪律。

## 覆盖率锁定

三 app 四指标锁定,**只升不降**;实际值高出锁定线 >2pp 时手动上调阈值并 commit(顺手收紧,不白涨)。

## 静态台账

- 圈复杂度 ≤15 / 模块 ≤400 行:新文件必须达标,存量不得恶化
- 刷新台账:`node scripts/quality-baseline.mjs update`(默认 dry-run,`--write` 落盘)
- 临时豁免:`check --allow-degrade`,commit message 须注明原因

## 提交纪律

- bug 修复 commit 必须含对应「失败 → 通过」测试用例
- 涉扩展改动:**manifest.json version 补丁位 +1**(CLAUDE.md §7)
- 改 CLI 命令 / 选项 / scripts 工具:必须同步 [docs/skills/collector/SKILL.md](../skills/collector/SKILL.md)(qa 门会拦漂移)
