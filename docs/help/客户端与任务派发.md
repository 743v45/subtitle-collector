# 客户端与任务派发

"客户端" = 一个装了采集扩展的浏览器。多机采集、任务调度、命名管理都在这页。

相关:[[采集模型]]、[[环境变量]]

## 列出客户端

```bash
pnpm cli clients list
# 含离线客户端(DB 注册表合并在线态),显示名字、在线/离线时长
```

server 重启不丢注册表,旧 client_id 会留存。

web 客户端页轮询刷新(约 3s 一拍);**离线客户端卡片带灰字提示「离线中——远程操作按钮仅在线时可用」**,且不渲染上报/派发开关按钮(操作须在线)。

## 仅上报开关(任务派发管控)

某台机器只想贡献数据、不想被派活(比如日常用的笔记本):

```bash
pnpm cli clients task-dispatch <clientId> off    # 关:仅上报状态,调度器不派任务,保持连接
pnpm cli clients task-dispatch <clientId> on     # 开:恢复接单
```

- **popup / options 里也有此开关**
- **web 客户端页**:开关旁有派发关语义说明(关后仅上报、任务派给其他机器);重试批量任务时提示带跳过计数(非可重试行不重复提交)
- 多客户端时,任务派给开着的机器;**全关则任务留 pending**(排错见 [[排错]])
- 另有 `reporting` 开关(上报总开关,日常不动):
  ```bash
  pnpm cli clients reporting <clientId> off
  ```

## 客户端命名

- **popup 底栏「改名」**:id 不变,名字本地落盘并经 hello/client-name-state 同步 server 持久化,清空保存即删除
- `clients list` 显示名字

## 登录态(判因)

`clients list` 与 web 客户端页每台客户端带 **B 站 / YouTube 双平台登录态**(离线也留存,显示最后上报的状态;null = 旧版扩展未上报过,升级扩展后出现)。

| 平台 | 未登录的后果 | 恢复方式 |
|---|---|---|
| B 站 | 充电视频 AI 字幕接口返回空——派给该客户端的批量采集会**整批 no_subtitle** | 在该浏览器登录 B 站,自动恢复上报 |
| YouTube | 年龄限制视频播不了、字幕 pot 受限加重——批量 **no_subtitle / pot_limited** 的判因依据 | 在该浏览器登录 YouTube,自动恢复上报 |

- popup 平台头也按当前平台显示登录徽章(B 站可点切昵称/UID;YouTube 无账号字段只显已/未登录)
- 抖音暂无登录徽章(远期);博主批量报「需登录」时按 [[排错]] 的抖音条目人工判因
- 批量采集整批 no_subtitle 时,先看这里判因:未登录 → 去浏览器登录;已登录 → 见 [[排错]] 与 [[无字幕视频处理]]

## 下发命令并等回执

```bash
pnpm cli clients command <clientId> <action> [--op <op>] [--url <url>] [--vid <vid>] [--timeout <ms>]
```

wait 恒真,`--timeout` 控制上限。

## 排序

`clients list --sort <key> [--desc=false]`:最近活跃 / 首次见到 / 名字,默认最近活跃在前。

web 采集任务历史页「第 X / Y 页 · 每页 20 批/条」里的数字即**展示单元**数(整批算 1);删除批次成员后页脚计数以服务端重拉为准。

## 采集任务查询与重试(tasks)

采集任务(批量采集的排队与执行记录)的查询与失败重试:

```bash
pnpm cli tasks list --status failed,limited    # 失败/受限任务(默认最近 20 条,created_at 降序)
pnpm cli tasks list --limit 5                  # 最近 5 条
pnpm cli tasks get <taskId>                    # 单任务详情(失败原因 error、回执摘要 result)
pnpm cli tasks retry <taskId> <taskId>         # 多 id 批量重试(非可重试行跳过,看回执 retried 计数)
```

- 更多筛选:`--source <平台>` / `--creator` / `--creator-uid` / `--q` / `--since --until` / `--batch-id`;翻页 `--page --page-size`;排序 `--sort created_at|finished_at|status`(升序 `--desc=false`)
- **翻页按「展示单元」真分页**(`--page --page-size` 与 web 历史页同口径):单条任务 = 1 单元、整批 = 1 单元,整批必落同一页(单元内全部成员行都返回,条目数可能超过 page_size);web 历史页每页 20 单元。仅 `--limit` 不带 `--page` 时仍是旧的「最近 N 行+批次补全」形态
- 默认连本地 dev 库;查生产加 `--server https://collector.local.taevas.host --token <t>`(没给 `--server` 时 CLI 会在 stderr 提示当前连的是 dev 库)
- 退出码:0 成功 / 2 参数错 / 3 server 不可达 / 5 任务不存在
- 批量采集整批失败的判因:先看上方「登录态(判因)」表,再 `tasks get` 看失败原因
