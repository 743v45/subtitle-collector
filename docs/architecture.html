五条核心数据流

  • ① 字幕采集 → 落库（三平台双路径）：被动路径 = 页面 fetch/XHR → inject（MAIN hook）postMessage → content（ISOLATED 聚合）→ chrome.runtime INGEST → background sendIngest → WS /ext · ingest → ingestVideo 单事务 upsert（(track_id, origin, asr_engine, source_url) 幂等去重）。主动路径 = server 建任务 → WS command（fetch-subtitle / fetch-youtube-subtitle / fetch-douyin-subtitle）→ background 后台 tab 导航到视频页取数（B 站为页面外直调 wbi API）→ 回执入库；抖音接口带页面签名，只能页面上下文取数（dy-navigate.mjs）。
  • ② 反向控制（server → 扩展）：CLI/前端调 POST /api/clients/:id/command → server 经 WS 下发 {id, action, ...} → background.js L557-914 派发，13 分支 / 14 个 action（navigate / operate / search / fetch-subtitle / fetch-youtube-subtitle / fetch-douyin-subtitle / expand-douyin-upper / get-upper-info / list-upper-videos / list-yt-channel-videos / yt-search / list-season-videos / set-reporting / set-task-dispatch，其中 fetch-douyin-subtitle 与 expand-douyin-upper 共用分支下沉 dy-navigate.mjs）→ 执行后回 result；不认识的 action 回 needs_update（版本感知派发门槛在 upper-expand.ts）。
  • ③ ASR backfill 兜底转写（server 侧，不走扩展）：CLI asr backfill --source bilibili|douyin（asr.ts）——圈定 no-subtitle 视频（GET /api/videos）→ B 站 wbi/view/playurl 直连拉音轨（asr-bili.ts）或抖音 extra.play_uri 直构 snssdk 直链下载 mp4（asr-douyin.ts，零 cookie，500MB 上限）→ 本机 fireredasr-ui（FireRedASR-AED-L）转写 → POST /api/asr/submit（http/asr.ts）入 asr-zh-<engine> 轨、幂等去重、成功摘 no-subtitle 标。
  • ④ 消费端闭环（分析原料 → 产物）：scripts/export-bundle.mjs 一条命令 = 生产库容器内 VACUUM INTO + docker cp 快照到 data/exports/ → collector-cli export bundle 出包 → analysis/<主题>/bundle/（manifest.json + ANALYZE.md + videos/*.txt）→ Claude Code 会话分析 → 产物落 analysis/<主题>/，最终报告住仓库外 report 仓库（官方流程 docs/help/分析工作流.md，已实跑 4 例）。
  • ⑤ 本地转写（VoiceCatch，😴 休眠）：inject 读 __playinfo__ 音轨 → background 免 CORS 抓 m4s → base64 → offscreen 跑 @voicetxt/core Whisper → SRT/VTT/TXT。与 collector 系统零代码耦合；voicetxt 失源后退役为备选，无字幕兜底职责移交数据流 ③。

容易被忽略的边界

  • 构建期耦合 collector-web 不是独立部署：vite build.outDir 直接写到 ../collector-server/public，运行期纯同源 REST（BASE=''），无 CORS / 无 token（dev）。dev 代理 /api、/ping → 127.0.0.1:21527；生产随 docker 镜像带上同一份产物。
  • 生产部署红线 生产真源 = docker named volume subtitle-collector_collector-data（2026-08-24 两次 SQLITE_CORRUPT：bind mount 走 virtiofs，宿主进程直触挂载库哪怕只读也会 mmap 一致性损库）——禁 bind mount、禁宿主直读库文件，查生产一律走 server HTTP 或 docker exec。网关 = caddy（*.taevas.host 子域名分发，现行生产入口 https://collector.local.taevas.host，见 网关设计 与 SKILL.md 双库表）；暴露部署 token 强制 + Host/Origin 白名单（main.ts）。本地 127.0.0.1:21527 仍是 dev 库；CLI 直连远端被 Host 校验 403 时的桥接代理：scripts/proxy-collector-server.mjs（127.0.0.1:21528 重写 Host 透传）。备份通道：db/backup.ts 每 15min 容器内 VACUUM INTO + 分层滚动（最近 8 份 + 每日末份 × 14 天）+ 连续失败 ≥2 次飞书 webhook 告警（异地副本走 backup-export.mjs）。
  • 外部依赖 @voicetxt/core 经 file: 协议指向仓库外同级目录且当前失源——subtitle-extractor 已从 pnpm-workspace.yaml 正式排除（测试冻结），休眠保留；fireredasr-ui 是独立项目，本仓库只经 HTTP 配置接入（默认 127.0.0.1:5079），缺能力去上游补码不在本仓库内嵌。
  • 分析产物边界 analysis/ 只存原料（bundle）与分析中间产物；最终报告住仓库外 report 仓库（Code/report/projects/subtitle-collector/），落盘规范锚点在 README「分析产物规范」条目。

编排

  • turbo（turbo.json）：tasks = build / dev / test，test 依赖 ^build；collector-android 走原生 gradle 链，刻意不进 turbo（package.json scripts 用 assemble/unit-test/lint 命名防误挂）。
  • 根脚本（package.json）：test:ext / test:youtube 走 scripts/verify-*.mjs（puppeteer mock 扩展，--load-extension=dist）；cli、collect-uppers、qa 全量质量门。
  • 端口/Token：dev 固定 127.0.0.1:21527；生产经 caddy https://collector.local.taevas.host（token 强制）。server 列表存扩展 storage，popup 可改（不再有 config.js 常量）；环境变量见 .env.example。
