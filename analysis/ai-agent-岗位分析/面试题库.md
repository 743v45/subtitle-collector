## 一、Agent 架构与编排

### Q1. 从零搭建一套 AI Agent 系统，到底该选哪种架构？（主流架构有哪些、各自优缺点与选型逻辑）

- **考点**：架构选型能力——是否只知道 ReAct / 多智能体两种，能否按业务复杂度与可控性要求匹配架构。
- **参考答案**（视频明说）：
  - 先记三个核心底层逻辑：①架构没有绝对好坏，选型只看两点——业务场景复杂程度、对系统可控性的要求；②Agent 迭代演进路径清晰：基础单智能体 → 多智能体协同 → 可视化图形工作流；③若赛道是 AI 代码编程/技能自动化系统，「路由+技能」架构是目前行业最优、落地最多。
  - 七种主流架构：
    1. **单 Agent 基础架构**：一个大模型全权承接思考/工具调用/输出全流程（早期 ChatGPT 是典型）。优点：搭建简单、成本低、延迟快；缺点：复杂多步骤任务认知超载、上下文混乱，扛不住复杂多并发业务。
    2. **ReAct 推理行动架构**：Reason + Act，闭环循环「思考推演→执行动作→观测结果→二次复盘」。有完整链式推理、可追溯可解释；缺点：token 消耗极高、运行稳定性差、推理易跑偏，不适合大规模工程化落地。
    3. **Plan-and-Execute 规划执行架构**：先整体规划（生成完整任务步骤清单）再分步执行，适配代码生成、长流程自动化，稳定性远超 ReAct；致命短板：前期规划一旦偏差，后续执行全部出错，灵活性不如 ReAct。
    4. **多 Agent 协同架构**：多智能体分工协作 + 顶层统一任务调度 + 底层规划/审核/执行等专属角色。任务拆分清晰、有效避免上下文污染、可扩展性极强；缺点：部署和运维成本偏高，适合流程规范、一致性要求高的复杂行业场景。
    5. **Router + Skill 路由技能架构**：核心精髓「不让模型盲目思考，让模型精准选择」——意图路由模块精准识别后调度对应专属技能模块（各配独立执行能力+专属知识库）。运行稳定、企业级可控、支持数据缓存、响应快、效果可量化；绝大多数 AI 编程智能/自动化系统清一色采用；缺点：前期技能模块设计成本高，偶有路由匹配冲突。
    6. **Blackboard 黑板架构**：共享状态驱动，多智能体同时读写同一公共状态池，靠状态变化推进任务。适配复杂多方协同；弊端：状态管理逻辑繁重、出问题排查溯源难度极高（LangGraph 等主流工作流引擎、分布式系统多基于此思路）。
    7. **Graph Workflow 图形工作流架构**：依托有向无环图完成全流程编排，支持条件分支、并行执行、重试、流程回溯，代表工具 LangGraph / Temporal / n8n / Prefect。七套中最重但稳定性最强、全程可调试、适配超长流程任务，是商业化生产环境自动化流程的最优解。
  - 选型总结：「没有万能的 Agent 架构，只有适配场景的最优架构」，按自身业务复杂度按需选择。
  > 来源: 【面经合集】[00:25]、[00:46]、[01:08]、[01:32]、[01:56]、[02:19]、[02:42]、[03:13]、[03:34]、[03:55]
- **常见追问**（分析者推断）：让你现场给一个业务场景（如客服、编码助手）选架构并说理由。

### Q2. ReAct 架构的核心逻辑是什么？它有什么致命缺陷？

- **考点**：对最经典 Agent 范式的理解深度，以及「知道缺点」的工程判断力。
- **参考答案**（视频明说）：ReAct = 推理（Reason）+ 行动（Act），运行逻辑是闭环循环：思考推演 → 执行动作 → 观测结果 → 二次复盘，循环往复直到任务完成。对比单 Agent 拥有完整链式推理能力，执行过程可追溯、可解释；但 token 消耗极高、运行稳定性差、推理过程容易跑偏，并不适合大规模工程化落地。
  > 来源: 【面经合集】[01:32]、[01:48]、[01:51]
- **常见追问**（分析者推断）：和 Plan-and-Execute 对比怎么选——见 Q3。

### Q3. Plan-and-Execute 和 ReAct 怎么取舍？

- **考点**：两种范式的工程权衡。
- **参考答案**（视频明说）：Plan-and-Execute 先通过模型生成完整任务步骤清单，再按既定步骤逐一落地，非常适配代码生成、长流程自动化场景，整体稳定性远超 ReAct；但存在致命短板——前期规划方案一旦出现偏差，后续所有执行步骤都会全部出错，整体灵活性远不如 ReAct。
  > 来源: 【面经合集】[01:56]、[02:10]、[02:12]
- **常见追问**：如何缓解「规划偏差全盘皆输」（视频未展开，仅出题方向）。

### Q4. 路由+技能（Router+Skill）架构为什么被推荐为落地性价比最高？

- **考点**：企业级可控性与确定性设计的理解。
- **参考答案**（视频明说）：核心理念是不让模型盲目思考、让模型精准选择：用户指令先经意图路由模块精准识别，直接匹配调度对应专属技能模块执行，每个技能搭配独立执行能力和专属知识库。优势：运行稳定、企业级可控、支持数据缓存、响应速度快、效果可量化评估——目前绝大多数 AI 编程智能、自动化系统清一色采用这套方案。缺点：前期技能模块设计成本较高，偶尔出现路由匹配冲突。
  > 来源: 【面经合集】[02:42]、[02:49]、[03:01]、[03:05]
- **常见追问**：路由匹配冲突怎么解（视频仅提及缺点，未给解法）。

### Q5. 多 Agent 协同架构的优势与代价？Multi-Agent 真正的难点是什么？

- **考点**：多智能体系统的分工调度与上下文管理。
- **参考答案**（视频明说）：多 Agent 采用分工协作模式，不同 Agent 承担不同职责，顶层设统一任务调度分配系统，底层搭配规划/审核/执行等专属角色。核心优势：任务拆分清晰、有效避免上下文污染、系统可扩展性极强；唯一不足是部署和运维成本偏高，更适合流程规范、一致性要求高的复杂行业场景。
  > 来源: 【面经合集】[02:19]、[02:32]
- **Multi-Agent 的真正难点**（视频明说）：任务怎么拆、前后依赖、context 传递；建议了解 OpenAI Agents SDK 里 sub-agent 的设计原理。
  > 来源: 【秋招盘点】[01:36]、[01:39]、[01:41]、[01:45]
- **常见追问**（分析者推断）：让你对比多 Agent 协同 vs 路由+技能在同一业务下的成本与可控性。

## 二、RAG 与检索

### Q6. 「会做一个普通 RAG」为什么不够？混合检索（Hybrid RAG）解决什么问题？

- **考点**：真实企业 RAG 场景的复杂度——异构数据、精确检索、问答质量。
- **参考答案**（视频明说，以某大厂 JD 为例）：安克的岗位表面上只要求 RAG、好像很简单，但实际要求把公司里乱七八糟的文档——原理图、板卡、芯片驱动、历史代码文件、各种格式的文件统一起来，让 AI 能精确找到并回答问题，所以要求对 hybrid RAG（混合检索）有一定理解，「只会做一个普通的 RAG 是没有用的」。
  > 来源: 【秋招盘点】[00:39]、[00:44]、[00:51]、[00:55]
- **常见追问**（分析者推断）：结构化/非结构化混合数据（图表、代码、驱动文档）如何统一入库与检索。

## 三、模型层与微调

### Q9. 你的 AI 项目动过底层模型吗？（后训练 / 强化学习微调改造）

- **考点**：区分「纯调 API 跑工程的后端开发」与「有理论深度的 Agent 开发」——大厂面试的第一个核心维度。
- **参考答案**（视频明说，考察框架）：大厂面试官希望通过面试测出理论深度和工程深度。如果一个 Agent 项目只是调 API、纯跑工程，那就是后端开发工程师的角色，测不出理论。要能答上：有没有针对 embedding 模型的特定优化、意图识别模型的后训练/强化学习微调改造、底层调用模型的改造。
  > 来源: 【大厂两点】[00:00]、[00:13]、[00:19]、[00:35]
- **面试趋势**（视频明说）：涉及微调和算法的面试问题越来越多——找大模型应用开发岗，面试官也会问到 20%–30% 的微调和大模型算法问题，例如 PyTorch 的问题、大模型自注意力机制的问题、归一化公式的问题；而今年年中之前几乎不会有面试官问这些。
  > 来源: 【码士面试】[05:09]、[06:49]、[06:57]、[07:00]、[07:05]、[07:13]
- **常见追问**（分析者推断）：让候选人讲一个自己微调过的具体模型与前后指标对比。

### Q10. 为什么现在面应用开发岗也要考自注意力机制、归一化公式这类算法八股？

- **考点**：对面试市场变化的认知（准备策略题）。
- **参考答案**（视频明说）：2025 年就业市场三大变化之一——「涉及到微调和算法的面试问题越来越多」（另两个变化见 Q26/Q27 的岗位认知部分）。因此「只学 Agent、RAG、私有化部署和推理就去找大模型应用开发岗」的策略失效了，纯大模型岗位从三个收敛为两个，准备面试时必须补微调与算法基础。
  > 来源: 【码士面试】[05:09]、[06:22]、[06:49]、[08:44]
- **参考答案的视频原话边界**：视频给出的是趋势判断与题目举例（PyTorch、自注意力、归一化公式），未讲解具体答案。

### Q16. 真正上线的智能体和 demo 差在哪？（状态管理 / 断点恢复 / 日志监控 / 风险防护 / 成本优化）

- **考点**：生产环境能力——「决定你做出来的是玩具还是产品」。
- **参考答案**（视频明说）：真正上线的智能体会报错、会中断、会等待人工审核、会恢复执行，所以状态管理、断点恢复、日志监控、风险防护、成本优化缺一不可；前两点（任务拆解、工具调用）决定你能不能做出来，后两点（评测调试、生产交付）决定做出来的是玩具还是产品。另一视频同口径：模型答错怎么办、工具调用失败怎么办、权限/成本/延迟怎么控、怎么做评测监控和人工兜底——这些才是 demo 和真实项目最大的差距；企业要的不是能跑一次，而是能上线、能稳定跑、出了问题还能查。

## 六、需求澄清与交付流程（FDE 实战题）

### Q21. 客户只给一句模糊需求（「我想要一个 AI」），怎么把它变成可验收的线上系统？

- **考点**：FDE 交付全流程——从需求发现到生产上线的完整链路。
- **参考答案**（视频明说，六/七步流程）：
  1. **澄清需求**：把一句话的模糊需求变成方案——客户到底要什么、做成什么才算成功；先问我要做什么、做到什么程度算完；
  2. **定契约**：数据长什么样、字段怎么对齐、拿不准的内容谁来拍板；
  3. **处理脏数据**：格式不统一、口径打架、缺字段——真实数据从来都有各种问题；
  4. **做出来**：AI 时代这一步反而最快，AI 可以自己开发项目；
  5. **人工检验自测**：AI 说测好了不算，必须人工再检验、也要求它再自测，确认没问题才可上线；
  6. **上线交付**，最后**验收**确认是否真的做完了。
  > 来源: 【FDE实战】[10:14]、[10:21]、[10:42]、[10:57]、[11:19]、[11:35]、[11:44]、[11:56]、[17:11]
- **与大厂 JD 的映射**（视频明说，主播原话）：S1「一句话变成可验收标准」对应阿里 JD「明确目标边界与验收标准」；S2 字段映射对应腾讯 JD「MCP 打通 CRM/ERP/OA」的字段对齐活；S5 自己挑毛病对应字节 JD「构建评估管道和可观测框架」、腾讯 JD「客户高管沟通与现场问题拆解能力」。
  > 来源: 【FDE实战】[47:52]、[48:02]、[48:12]、[48:23]、[48:31]

### Q22. 提示词工程实战：怎么让 AI 替你做需求澄清——既不瞎猜、也不陷入死循环？

- **考点**：对 AI 编码工具的驾驭能力（提示词设计原则）。
- **参考答案**（视频明说，设计原则）：放开让 AI 随便问，它会问「该怎么想」想了半小时一个字说不出；完全不问直接写，写出来大概率不是想要的。所以规则是：**不许提问，拿不准的必须写假设**——猜可以，但必须留痕；这份假设清单就是需要跟客户逐条确认的问题清单。配套执行约束：直接在对话框回答不写文件、限字数、不要反复推敲措辞顺序、想清楚立马给结果，防止陷入死循环。
  > 来源: 【FDE实战】[22:50]、[23:00]、[23:36]、[23:41]、[23:52]、[22:26]、[22:43]
- **常见追问**（分析者推断）：这套「假设留痕」机制如何沉淀为团队的需求确认模板。

### Q23. 客户一定会问「这个数据怎么来的」——脏数据处理怎么做才可交付？

- **考点**：数据契约与可审计性。
- **参考答案**（视频明说）：同一岗位在不同公司叫法完全不同（例：四家大厂分别叫「AI 前线部署工程师」「forward deployed engineer」「前沿部署工程师」「客户技术解决方案架构师 FDE 方向」，还有公司叫「交付中心」），实际干的活一样；抓取的数据有的全文、有的只有几个要点，技能点散落在岗位职责、岗位要求、加分项三个地方，粒度不齐，需要按事先约定的 PRD 契约（JSON 字段设计+映射表）归一，拿不准的归类单独列出待人工复核。真实交付里客户一定会问数据来源，要答得上——这叫可审计。
  > 来源: 【FDE实战】[28:42]、[29:25]、[29:38]、[29:49]、[29:56]、[30:54]、[30:56]

## 七、岗位认知与开放题

### Q24. FDE（前沿部署工程师）是什么？不是什么？

- **考点**：对新岗位边界的理解（岗位认知题）。
- **参考答案**（视频明说）：
  - **是什么**：在 AI 工具加持下，到客户现场把客户的需求变成跑得通的、生产环境可使用的系统；不研究模型，是让模型在客户生产系统上落地。另一视频口径：把大模型/RAG/Agent 这些前沿技术真正接进企业业务，并对落地结果负责；会调 API、会搭 agent demo 只是入门。
  - **三个不是**：①不是售前——售前讲完方案签完就交出去，FDE 是签完合同才开始，腾讯 JD 原话「主导落地交付上线护航」；②不是运维——运维保证系统不挂掉，FDE 决定系统该变成什么样子，字节 JD 原话「独立完成技术架构决策」；③不是驻场外包——外包按人天出活听甲方指挥，FDE 对客户业务结果指标负责。
  - **本质**：一个人代表一个团队（AI 工程师+产品经理+技术顾问+项目交付），更偏中高级岗位；FDE 有两种形式——去客户现场的驻场 FDE 和公司内部的 FDE（有的公司叫 AI BP）。
  > 来源: 【FDE实战】[05:12]、[05:34]、[07:21]、[08:16]、[08:22]、[08:33]、[08:44]、[08:59]、[09:13]、[09:26]、[12:28]、[12:37]；【FDE薪资】[00:12]、[00:20]、[01:12]、[01:18]

### Q25. 大厂 Agent 岗面试官到底看重什么？

- **考点**：面试策略题（本原料中出镜率最高的元问题）。
- **参考答案**（视频明说）：两点——**理论深度**与**工程深度**。理论深度：有没有动底层模型（embedding 优化、意图识别模型后训练/强化学习微调、向量库召回提升、rerank 二次微调），只调 API 纯跑工程测不出理论。工程深度：面试官喜欢不停地追问——高并发、异步、长短期记忆几层机制、缓存设计、TTFT 优化轮次、用户量涨 10 倍/100 倍的方案、模型宕机兜底、服务堵塞降级。
  > 来源: 【大厂两点】[00:00]、[00:13]、[00:59]、[01:01]
- **同口径印证**（视频明说）：企业拿着几十万预算招不到人，因为很多人学的东西不少、但学的不是企业需要的能力——以为会搭工作流、会调 API 就能做智能体，实际这只是入门；真正值钱的是四大能力（任务拆解/工具调用/评测调试/生产交付）。
  > 来源: 【四大能力】[00:00]、[00:18]、[00:21]

### Q26. 只会 Agent、RAG、部署推理，为什么找不到纯大模型岗位了？

- **考点**：岗位市场认知（求职策略题）。
- **参考答案**（视频明说）：2025 年上半年（6 月前）简历上写一个智能体+一个简单 RAG 就大概率能找到工作；7 月开始面试越来越难；年底面试官开始问微调与算法（占 20%–30%），因此「纯大模型岗位有三个」修正为两个（大模型研发/应用算法工程师、大模型算法工程师），只学应用开发那一小部分找纯 AI 大模型岗位「有点难了，几乎可能找不到」。该 UP 同时给出口径：今年 10 月前其学员就业没有一个低于 2 万月薪，11–12 月已出现多个低于 2 万（含 17K offer），年底薪资不好谈。
  > 来源: 【码士面试】[02:41]、[02:56]、[05:40]、[06:22]、[06:49]、[07:56]、[08:44]、[03:07]、[03:44]、[03:50]
- **注意**：以上为该 UP 基于其学员样本的说法（涉及招生营销动机，分析者提示需谨慎采信），非行业统计数据。

### Q27. 开放案例题：判作业、批量生成人物视频这类需求，怎么用智能体做？

- **考点**：用 workflow 思维拆解批量重复业务。
- **参考答案**（视频明说，UP 的讲解案例）：智能体（agent，直译「代理」）做的就是 workflow 工作流——把流水线的活交给 AI 助手让它自己批量完成。案例一：老师判作业，200 个学生重复判 200 次，搭好流程后拍照上传，每道题对错、错在哪、分自动出；案例二：输入一个人名，自动批量生成「某人物的一生」类视频。配套岗位观察：上海有「扣子智能体」「智能体搭建师」等岗位，部分岗位学历大专/不限。
  > 来源: 【工作案例】[00:48]、[00:53]、[01:33]、[01:40]、[01:58]、[02:22]、[00:15]、[00:26]
